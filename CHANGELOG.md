- WhatsApp chat vault added on the server (`chats.py`, `server.py` `/chats`, `/api/chats/status`, `/api/chats`, `/api/chats/<id>/messages`, `/api/chats/thumb/<id>`, `/api/chats/import`, `STASH_CHATS_MAX_MB` default 512, `STASH_CHATS_KEEP` default 3), with `tests/test_chats.py` and `tests/test_chat_media.py` (was: no chat backup or viewer)

- WhatsApp chat viewer (`chats.html`) rewritten with `index.html`'s colours and button press feedback, splash and busy indicators, inline chat media and thumbnails linked strictly by SHA-256, narrow-screen list/chat switching plus solo-chat mode (`?c=`), chat and in-chat search, "Load earlier messages" with IntersectionObserver auto-paging and scroll fade, shared light/dark `theme`, `window.stashBack()`, and fixes for the concurrent `load()` race, `#qrow` visibility, and date wrapping (was: plain first-version desktop layout with no `index.html` link, no chat media, and no phone layout)
- `index.html` updated with a Chats button, WhatsApp source filter (`All files` / `WhatsApp only` / `Hide WhatsApp`), phone layout (`#fab`, `#moreBtn`, `#viewBtn`, long-press selection, bottom bulk bar, expandable upload sheet, viewer swipe, tap-to-hide), splash/busy/dialog animations, 72-item chunked rendering + scroll fade, targeted tile selection, reused `Intl` date formatters, and page slide transitions (was: desktop-first layout that rebuilt the whole grid on selection and recreated date formatters on every redraw)
- On-device WhatsApp `crypt15` and chat media backup added to the Android app (`Crypt15.kt`, `WhatsAppBackup.kt`, `StashApi.kt`, `Prefs.kt`, `BackupScheduler.kt`, `BackupActivity.kt`): 64-digit key decryption in 64 KB chunks (fixed full-chunk reads so the AES counter does not drift), SAF WhatsApp folder picker, 6-hour schedule, SHA-256-verified media backup (`X-Source: whatsapp`, 1-day default window), "Back up chats now", "Back up older media…", "Stop", and "Open chats" (was: photo and video backup only)
- `MainActivity.kt` updated with native layered WebViews for `/chats` and narrow-screen chats (`Stack` left-edge swipe, Android 14+ predictive Back, Android 10–13 gesture exclusion, `StashApp.openPage`/`closePage`, `EXTRA_PATH`), stepwise Back navigation on `/` (open `<dialog>` → `window.stashBack()` → leave app), `SwipeBack.kt` (`SwipeBackLayout`) on `BackupActivity.kt`, website file chooser switched to `ACTION_OPEN_DOCUMENT` starting at main storage so it does not reopen in the WhatsApp folder, 8-second `StashApi.session` pre-flight check, and reconnect reload on resume (was: single WebView, Back always left the app, picker opened in the last-used WhatsApp folder, and the error screen stayed on resume)
- Backup screen and scheduler (`BackupActivity.kt`, `BackupScheduler.kt`) watch network state and report `"Waiting for Wi-Fi (Wi-Fi only is on)"` plus a queued toast when held back without Wi-Fi (was: status stayed idle / `"Starting…"` when WorkManager waited for Wi-Fi)
- Default upload limit is now 10 MB, in the code and in the `server.py` header comment (was: 2048 MB in the code, while `GUIDELINES.md` and the README said 10 MB)
- Phone files over the server's size limit are counted as "too big" in the backup status and are no longer recorded as done, so they are tried again once the limit is raised; `backup.db` upgrades to version 2 and forgets old "skipped" rows once (was: they were recorded as "skipped" and never tried again)
- `GET /api/session` with a wrong `Authorization: Bearer` key is still counted toward the 10-failure limit, but is no longer delayed by 0.6 s and never answers 429; `authed` stays false while that client is blocked (was: delayed 0.6 s and answered 429 once the client was rate limited)

- `tests/test_session_counted.py` added: wrong key on `/api/session`, the 10-miss limit, a 16-character key, a server with no password (was: no test for these)
